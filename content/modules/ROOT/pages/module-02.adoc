= Module 2: Sandbox the Agent
:page-duration: TBD

// Overview: Participants learn the agent isn't sandboxed today, then place it in one, covering what
// OpenShell is (architecture and background). Once sandboxed, they confirm they're shielded from the
// earlier attacks -- but find the agent is now unable to do anything useful. Their job for the rest of
// the lab is to restore the agent's usefulness without losing that protection, using MLflow Evals
// instead of manual checks to see what's actually broken.

== Objectives

* Learn what OpenShell is: its architecture, background, and role in the lab
* Put Hermie in a box, re-run the earlier attacks and confirm the sandbox now shields the agent against all of them
* Discover that the sandboxed agent can no longer do anything useful, and understand why
* Understand your job for the rest of the lab: make the agent useful again without losing that protection
* Manually trigger evals to evaluate the agent's behavior in a sandbox

. Jump into the gateway pod where the mTLS client cert and key are. Because of the mTLS client cert, the gateway is only accessible from inside the cluster.
+
[source,bash]
----
POD=$(oc get pod -l app.kubernetes.io/name=hermes-openshell-bridge -o name -n {user}-agentops)
oc rsh -n {user}-agentops -c cli $POD
----

. Let's point to the OpenShell gateway so we can create a sandboxed Hermie.
+
[source,bash]
----
openshell gateway add https://{user}-openshell.{user}-agentops.svc.cluster.local:8080 --local --name openshell-gw
openshell gateway select openshell-gw
----

. Create the sandbox by pointing to the same image we use for the agent.
+
[source,bash]
----
openshell sandbox create --name hermie --from quay.io/rh-aiservices-bu/waterplant-hermes:0.2.2 --cpu 2 --memory 4Gi --no-tty -- true
----
+
. Hermie has user or environment specific configuration that we externalized, so we don't have to build it everytime a config changes (a good practice of software engineering). But because the way that OpenShell works, we cannot mount these configs inside the sandbox. Sandboxes are immutable. OpenShell does not allow any external configuration change tor reflect inside the sandbox immediately. So we have to copy the configuration files into the sandbox.
+
[source,bash]
----
openshell sandbox upload hermie /hermes /sandbox
----
+
. Alright, let's run sandboxed Hermie!
+
[source,bash]
----
openshell sandbox exec --name hermie -- start-hermes
----
+
[source,bash]
----
openshell service expose hermie 8080 openai

----

First get out of the OpenShell gateway pod and back to your local terminal. For that, just type `exit` in the OpenShell gateway pod terminal. Then run the following command to point the UI to the sandboxed Hermie.

[source,bash]

[source,bash]

Hermie complains that it cannot access to MCP Gateway and Keycloak. We need to apply a `network policy` to access these endpoint. Let's do that


And apply the policy that allows Hermie to access the model endpoint:
+
[source,bash]
----
openshell policy update hermie --rule-name keycloak_token --add-endpoint sso.{openshift_cluster_ingress_domain}:443:full:rest:enforce --binary /usr/bin/python3 --binary /usr/bin/python3.12 --wait
----
+
+
[source,bash]
----
openshell policy update hermie --rule-name mcp_gateway --add-endpoint mcp-gateway-data-science-gateway-class.{user}-agentops.svc.cluster.local:8080:full:rest:enforce --binary /usr/bin/python3 --binary /usr/bin/python3.12 --binary /usr/local/bin/hermes --wait     # MCP gateway so we can get access to tools
----

Restart Hermie, only needed for mcp_gateway because it fetches tools at startup, policies in general does not need restart.

openshell sandbox exec --name hermie -- start-hermes

→ Using sandbox 'hermie' (last used)
[1791795587.426] [sandbox] [OCSF ] [ocsf] HTTP:POST [MED] DENIED /usr/bin/python3.12(868) -> POST http://hermes-mlflow-relay.{user}-agentops.svc.cluster.local:8788/v1/traces [policy:- engine:opa] [reason:FORWARD denied POST hermes-mlflow-relay.{user}-agentops.svc.cluster.local:8788/v1/traces]

openshell policy update hermie --rule-name mlflow_tracing --add-endpoint hermes-mlflow-relay.{user}-agentops.svc.cluster.local:8788:full:rest:enforce --binary /usr/bin/python3 --binary /usr/bin/python3.12 --binary /usr/local/bin/hermes --wait     # MLflow access


Let's see if we have enough. Go back to UI, send a prompt, see if it works, and check the traces. If it still doesn't work, check the logs again, and apply any missing policies. You may need to restart Hermie after applying new policies.

# If you ever want to remove a policy, the mcp_gateway for example
You don't have to run it, but in case bla..
openshell policy update hermie --remove-rule mlflow_tracing --wait
openshell policy update hermie --remove-rule model_endpoint --wait
