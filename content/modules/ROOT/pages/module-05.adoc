= Module 5: Let the Agent Reach the Docs Website
:page-duration: 25 minutes

== Objectives

* Restore access to the documentation Hermie needs for safety questions
* Use a skill to select the documentation source without asking operators for URLs
* Investigate a prompt injection delivered through a documentation lookup
* Restrict network access by destination, HTTP method, and path
* Verify that legitimate documentation works while the unwanted destination is blocked
* Understand why approved sources can still contain untrusted instructions

=== Limit access to the documentation paths

We need to preserve the useful lookup while preventing the redirected request. The site serves its index at `/doc`, and its documents beneath `/doc/`. The attacker endpoint is outside those paths.

Adding a narrow allow rule alongside the original `full` permission would leave the broad permission in place. Let's remove the old rule first and add a replacement that explicitly allows only documentation reads.

. Remove the host-wide rule from inside the bridge CLI container:
+
--
[source,bash,role=execute]
----
openshell policy update hermie --remove-rule waterplant_docs --wait
----

Documentation access is now blocked temporarily. The other rules from the previous modules remain in place.
--

. Create the replacement rule with this copy-and-paste command:
+
--
[source,bash,role=execute]
----
cat > /tmp/hermie-docs-rule.yaml <<'EOF'
  waterplant_docs:
    name: waterplant_docs
    endpoints:
      - host: waterplant-docs
        port: 8080
        protocol: rest
        enforcement: enforce
        rules:
          - allow:
              method: GET
              path: /doc
          - allow:
              method: GET
              path: /doc/**
    binaries:
      - path: /usr/bin/python3
      - path: /usr/bin/python3.12
      - path: /usr/local/bin/hermes
EOF
----

Read the rule before applying it. It permits `GET /doc` for the index and `GET /doc/**` for the documentation pages. There is no broad `access: full` preset, and `/attack/collect` is not included. The indentation places this rule beneath `network_policies` in the complete policy.
--

. Add the replacement to the remaining policy:
+
--
[source,bash,role=execute]
----
openshell sandbox get hermie --policy-only > /tmp/hermie-docs-policy.yaml
sed '/^network_policies:$/r /tmp/hermie-docs-rule.yaml' \
  /tmp/hermie-docs-policy.yaml > /tmp/hermie-docs-policy.restricted.yaml
cat /tmp/hermie-docs-policy.restricted.yaml
----

The `sed` command inserts the new rule immediately beneath `network_policies:`.
--

. Apply the restricted policy and inspect the result:
+
--
[source,bash,role=execute]
----
openshell policy set hermie --policy /tmp/hermie-docs-policy.restricted.yaml --wait
----

Confirm that `waterplant_docs` contains only the two `GET` path rules. Check that no other rule grants broad access to the same destination.

[source,bash,role=execute]
----
openshell policy get hermie --full
----

Only network permissions changed, so sandbox recreation is not required. OpenShell checks the redirected HTTP request against the rules too; permission to read the starting URL does not authorize every destination it redirects to.

=== What did we learn?

You restored an operator's access to safety documentation, then investigated why that access exposed Hermie to an unexpected page. Restricting the hostname was a useful first boundary, but method-and-path rules made that permission match the documentation task more closely.

The policy stopped this delivery route. It did not solve every prompt injection problem. If malicious instructions appeared directly inside an allowed `/doc/` page, the fetch would still be permitted.

The sandbox puts a boundary around Hermie, defining which systems, files, and endpoints it can reach. But we also need to watch what happens inside that boundary. A compromised tool or document can influence the agent through an allowed interaction, leading to misleading advice or harmful actions using permissions it already has. Those actions can disrupt the business even without crossing the sandbox boundary.

That is why tracing and guardrails matter as well. You need to inspect what Hermie read, how it used that content, and whether its actions still serve the operator's request. Setting boundaries and checking the interactions within them are both part of operating the agent safely.

Onto the guardrails then!
